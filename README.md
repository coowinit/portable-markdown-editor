# Markdown 编辑器

一个轻量、可离线、零构建、本地优先的 Markdown 编辑器。

**打开即用 · 实时预览 · 自动保存 · 本地文件 · 响应式布局**

</div>

---

## 项目简介

这个项目面向一个很明确的使用场景：

> **需要快速打开一个 Markdown 文件，完成编辑、预览，然后把文件保存下来。**

它不打算成为完整的笔记系统、知识库或在线文档平台，而是把 Markdown 编辑最常用的一组能力整理成一个可以长期保存、随时复制、直接运行的小工具。

核心业务代码集中在 `index.html` 中，Markdown 解析库保存在本地 `vendor/` 目录。下载完整项目后，无需安装依赖、无需启动开发服务器，直接双击 `index.html` 即可使用。

```text
打开文件
   ↓
编辑 Markdown
   ↓
实时预览
   ↓
浏览器自动保存
   ↓
下载 Markdown
```

## 设计原则

这个版本的重点不是“功能越多越好”，而是保持清晰、稳定和容易维护。

| 原则 | 说明 |
| --- | --- |
| **Zero Build** | 不使用 npm、Vite、Webpack 等构建体系 |
| **Local First** | 正文和界面状态优先保存在浏览器本地 |
| **No Backend** | 不依赖 PHP、Python、Node.js 或数据库 |
| **Offline Ready** | 第三方依赖本地化，核心功能可离线运行 |
| **Pages Ready** | 可直接部署到 GitHub Pages |
| **Keep It Small** | 不为了增加功能而持续扩大项目复杂度 |

这一取舍也参考了原项目强调的“即开即用、本地保存、无需账号”的产品思路，但当前版本进一步收缩了功能边界，把重点放在 **Markdown 编辑本身**。

## 功能一览

### ✍️ Markdown 编辑与实时预览

桌面端采用左右双栏结构：

```text
┌─────────────────────┬─────────────────────┐
│                     │                     │
│       编辑区         │       预览区        │
│                     │                     │
└─────────────────────┴─────────────────────┘
```

支持常见 Markdown / GitHub Flavored Markdown 语法，包括：

- 标题
- 粗体、斜体、删除线
- 引用
- 行内代码、代码块
- 无序列表、有序列表、任务列表
- 链接、图片
- 表格
- 分隔线

### 🛠️ 快捷格式工具栏

编辑器顶部提供常用 Markdown 格式按钮：

```text
H1 / H2
粗体 / 斜体 / 删除线
引用
行内代码 / 代码块
无序列表 / 有序列表 / 任务列表
链接 / 图片 / 表格
```

工具栏只负责辅助插入 Markdown 语法，不模拟完整富文本编辑器，从而保持交互简单、实现轻量。

### ↩️ Undo / Redo

内置轻量编辑历史：

- 最多保存 100 个历史快照
- 连续输入后自动记录历史状态
- 工具栏格式化操作立即进入历史记录
- 支持撤销 / 重做按钮
- 支持键盘快捷键

### 📂 本地文件操作

支持：

- 打开 `.md`
- 打开 `.markdown`
- 打开 `.txt`
- 将 Markdown 文件直接拖入页面
- 自动读取并保留文件名
- 下载当前内容为 Markdown 文件

> 受浏览器安全机制限制，纯静态网页不能直接覆盖磁盘中的原文件，因此“保存”通过浏览器下载生成文件。这也是项目保持无后端、零构建架构的重要前提。

### 💾 自动保存

以下状态会保存到浏览器 `localStorage`：

- Markdown 正文
- 当前文件名
- 深色 / 浅色主题
- 桌面端编辑区与预览区比例

重新打开页面后，可以继续上一次未完成的内容。

所有自动保存数据均保存在当前浏览器中，不会主动上传到服务器。

### 🌗 深色 / 浅色主题

支持一键切换深浅主题，并自动记住用户选择。

### ↔️ 可拖动分栏

桌面端可以拖动中间分隔线，自由调整：

```text
编辑区  ⇆  预览区
```

分栏比例会自动保存，下次打开页面时继续沿用。

### 📱 响应式布局

在手机和平板窄屏下，编辑器不会强行压缩成两列，而是切换为单面板模式：

```text
┌──────────────────────┐
│    编辑   |   预览    │
├──────────────────────┤
│                      │
│      当前主面板       │
│                      │
└──────────────────────┘
```

移动端主要优化包括：

- 编辑 / 预览快速切换
- 16px 正文字号，改善输入与阅读体验
- 格式工具栏支持横向滚动
- 预览模式自动隐藏格式工具栏
- 顶部操作按钮保持单行显示
- 针对较窄平板窗口提前切换单栏布局

## 快速开始

### 方式一：直接打开

下载或克隆完整项目后，直接双击：

```text
index.html
```

即可开始使用。

不需要执行：

```text
npm install
npm run dev
npm run build
```

也不需要启动本地 Web Server。

> 请保留 `vendor/` 目录及其文件，否则 Markdown 解析功能无法正常加载。

### 方式二：部署到 GitHub Pages

项目入口就是根目录 `index.html`，因此可以直接作为纯静态页面发布。

基本流程：

1. 将完整项目上传到 GitHub 仓库
2. 打开仓库 **Settings**
3. 进入 **Pages**
4. 在 **Build and deployment** 中选择从分支部署
5. 选择需要发布的分支，例如 `main`
6. 选择 `/ (root)`
7. 保存并等待部署完成

无需额外构建配置。


| 技术 | 用途 |

## 安全边界

Markdown 预览不是简单地把生成的 HTML 直接写入页面，而是增加了基础安全处理：

1. Markdown 中的 Raw HTML 默认不会直接作为可执行 HTML 渲染
2. 渲染结果会经过标签和属性白名单过滤
3. `javascript:` 等危险 URL 协议会被拦截
4. 外部链接自动增加 `noopener noreferrer`
5. 任务列表中的输入框会被限制为不可编辑状态

设计目标很明确：

> **Markdown 预览不应该因为一个附加功能而默认获得执行任意 HTML / JavaScript 的能力。**

需要注意的是，当前过滤逻辑属于轻量安全边界，并不等同于专业 HTML Sanitizer 或完整的安全审计。

因此不建议把本项目作为处理完全不可信 HTML 的安全沙箱。

如果未来开放 Raw HTML，应优先引入经过长期验证的 HTML Sanitizer，而不是简单放宽现有过滤规则。

## 为什么保持轻量

原版 `lengyi-markdown-editor` 已经发展出较丰富的编辑能力，例如多语言、数学公式、Mermaid、更多格式工具以及多种导出方式。

这个项目并不是试图复制所有功能，而是选择另外一条路线：

```text
Markdown 核心编辑能力
          ↓
是否可以纯静态运行？
          ↓
是否明显改善日常使用？
          ↓
是否会增加长期维护负担？
          ↓
再决定是否加入
```

因此当前核心版本不会为了功能数量主动引入：

- npm 构建体系
- 前端框架
- 后端服务
- 数据库
- 云同步
- 用户系统
- AI 对话
- 在线网页采集
- 复杂文档管理

**保持功能边界，本身也是这个项目的一部分。**
